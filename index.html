What I did and how

End-to-end framework

Problem
A multi-region SaaS platform needed end-to-end checks a reviewer could follow without reading the automation API.
What I built
A Python 3.13 suite on pytest and Playwright sync, with a base page class and one wrapper per page, dialog, or wizard. Tests read like manual steps, and Playwright types stay out of them.
How
Logs are nested per phase and per step. Each test stores its own logs, screenshots, and network log. Size today: {{N_TESTS}} tests in {{N_MODULES}} modules, with {{N_PAGE_OBJECTS}} page objects.
Impact
A failure points at the step and the artifact for that test, so the suite can grow without becoming opaque.

Parallel-safe runs

Problem
Workers that run together still share one login, and SMS-capable phone numbers are too scarce to hand out twice.
What I built
pytest-xdist workers share one logged-in session. The phone-number pool is taken and released under file locks with timeouts, and each run uses unique data.
How
Fixtures tear the data down. Login uses TOTP-based MFA. API clients create the test data and check the responses.
Impact
Parallel runs do not take the same phone number, and they do not leave that data behind for the next run.

Reporting

Problem
A job log does not show whether the suite is improving, or whether a failure is flaky.
What I built
JUnit XML goes to a per-run HTML report and then to a cumulative dashboard: pass-rate trend, daily pass-rate chart, run-history matrix, and flaky versus real failures.
How
The dashboard is published to S3 behind CloudFront. Slack notifications carry a direct link to the run.
Impact
A lead can open the run, see the trend, and tell a flake from a real failure without asking for a pasted log.

CI for the suite

Problem
Post-deploy, nightly, and manual runs share test data, so the jobs have to take turns.
What I built
GitLab CI child pipelines on Kubernetes runners, with post-deploy and nightly runs plus manual jobs.
How
Resource groups serialize the jobs that share test data, and artifacts are retained. I also fixed a log flood in an after-script.
Impact
Shared-data jobs wait their turn, and the after-script no longer buries the job log.

Flaky tests

Problem
Suspend and unsuspend, and application scanning, failed on and off. Filter changes and two UI versions made the same failures worse.
What I built
Locators that work on the old and the new UI, and backward-compatible checks for filters that changed.
How
A step waits until the screen shows the state it needs, instead of sleeping for a fixed time.
Impact
Those flows stop failing only because the screen was mid-update or the locator assumed the other UI version.

AI-assisted QA

Problem
Drafting a page object from memory was slow, and a locator could miss the UI that was actually on screen.
What I built
Reusable agent skills that inspect the live UI through Chrome DevTools MCP, choose semantic locators, scaffold the page object and the test, run a focused check, and self-review against team standards.
How
AI code-review rounds run before merge.
Impact
A new test is checked against the live UI and team standards before it is merged.

How I work

  1. Tests read like the manual steps

    Playwright stays in the page objects. A reviewer should be able to follow the test the way they would follow a written case.

  2. Parallel runs get their own data

    One shared login is enough. Scarce phone numbers are locked, used once, and returned. Teardown puts the pool back.

  3. A failure keeps its evidence

    Logs, screenshots, and the network log stay with the test. The dashboard separates flakes from real failures.

  4. Wait for the screen, not the clock

    Readiness comes from visible UI state. Locators work on the old and the new UI, including filters that changed.

  5. A draft is not a merge

    An agent can scaffold a test from the live UI. Review against team standards still happens before merge.

Behind the video

The demo is an animated HTML and CSS storyboard. Frames are captured with Playwright and Chromium, then encoded with ffmpeg at 1920×1080 in H.264. Narration is text-to-speech from edge-tts.

I cut it from 15 seconds to 20 seconds. This page uses the 60-second cut. The player loads assets/demo.mp4 and assets/demo.webm from this site.

Sample suite

This is a small public stand-in for the same approach. It targets practicesoftwaretesting.com only. The catalog there is synthetic.

Eight UI checks cover search, a category filter, price sort, a product page, cart math, sign-in, invoices (the shop’s order history), and an out-of-stock control. Three API checks validate product and category payloads with pydantic. Page objects use role-based locators. There are no fixed sleeps.

Sign-in uses the shop’s built-in customer account. Reports land in sample-suite/reports/junit.xml and sample-suite/reports/report.html.

cd sample-suite
python3.13 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m playwright install chromium
python -m pytest

The shop refuses a headless Chromium. Run the command on a machine with a display, or use xvfb-run -a python -m pytest on Linux.
