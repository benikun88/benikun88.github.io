Re-render

uv venv --python 3.13 .venv
source .venv/bin/activate
uv pip install -r video/requirements.txt
python -m playwright install chromium
python video/render.py

The script starts xvfb itself when DISPLAY is unset. It needs network access for the practice shop and for the edge-tts voice. python video/render.py --reuse-build keeps an existing JUnit file and tour recording and still rebuilds the voice, frames, and encodes. --preview-slides writes stills only, with placeholder counts, and does not call the shop.

Title cards are headless screenshots of local HTML. The shop tour is headed Chromium. The page content, prices, and copy are the live site. Corner controls on the shop can remain visible.

Sample commands the render runs

python -m pytest video/public_sample/test_shop.py --junitxml video/build/junit.xml
# headed Playwright tour of the practice shop, video saved under video/build/tour/
ffmpeg -i video/build/picture -i narration.wav -c:v libx264 -pix_fmt yuv420p -crf 26 -r 30 -c:a aac -movflags +faststart assets/demo.mp4
ffmpeg -i assets/demo.mp4 -c:v libvpx-vp9 -pix_fmt yuv420p -crf 34 -b:v 0 -c:a libopus assets/demo.webm

The exact ffmpeg invocations are printed by video/render.py when it runs. Intermediates stay in video/build/ and are gitignored. If demo.mp4 ever exceeds 25 MB, the script stops and does not treat that file as shippable. The fallback would be an unlisted embed on youtube-nocookie.com, not a larger file in git.
